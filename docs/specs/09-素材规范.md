# 09 素材规范（用户提供素材 / Codex 实现加载）

> 本章同时给**用户**（准备素材）和 **Codex**（写加载与校验代码）看。
> 核心原则：**任何素材缺失，游戏都能用占位方案照常运行。** 地表和水面贴图由开发者负责。本版使用生图模型绘制的底图加工成可平铺纹理，再制作配套的法线和粗糙度图。其他素材可以分批提供。

## 9.2 manifest.json

完整文件已经由规划方提供：`public/assets/manifest.json`（随种子文件一起复制进仓库）。结构如下（节选）：

```json
{
  "version": 1,
  "cars":   { "hatch": { "model": "cars/hatch/hatch.glb", "engine": [ { "file": "...", "rpm": 2000, "load": "on" }, "..." ] }, "coupe": {}, "rally": {} },
  "env":    { "valley": { "hdri": "env/valley_sky.hdr", "sunU": 0.25 }, "coast": { "hdri": "...", "sunU": 0.25, "waterNormals": "..." } },
  "track":  { "asphalt": { "albedo": "...", "normal": "...", "rough": "..." }, "grass": {}, "gravel": {}, "concrete": {}, "rock": {} },
  "scenery":{ "tree_a": "scenery/tree_a.glb", "...": "..." },
  "audio":  { "tyre_skid": "audio/tyre_skid.wav", "...": "..." }
}
```

TS 类型写在 `src/assets/manifest.ts`，与文件结构一一对应，所有路径字段都是可选的（`string | undefined`）。

`sunU`：HDRI 里太阳所在的水平位置，等于"太阳中心的像素列 ÷ 图片宽度"，取值 0–1。**用户提供 HDRI 时要填这个值**，用图片查看器量一下即可。

## 9.3 车辆模型（每辆车一个 .glb）

| 要求 | 内容 |
|---|---|
| 格式 | glTF 2.0 二进制（.glb），PBR metallic-roughness 材质 |
| 单位与朝向 | 1 单位 = 1 米；**+Y 向上，车头朝 +Z** |
| 原点 | 在**两根车轴中点**正下方的**地面**上（x=0 为车身中线，y=0 为轮胎触地点所在的地面） |
| 姿态 | 静止停放的姿态（车轮刚好接触 y=0 的地面） |
| 尺寸 | 必须与下表一致（误差 ±2 cm）：车轮中心的 x 坐标 = ±轮距/2，z 坐标 = ±轴距/2，y 坐标 = 车轮半径 |
| 节点命名 | 车身所有部件放在名为 `body` 的节点下；4 个车轮各自是独立节点：`wheel_FL`、`wheel_FR`、`wheel_RL`、`wheel_RR`（F=前，R=后/右，L=左，**左 = +X 方向**）；可选刹车卡钳节点 `caliper_FL` 等（只转向不旋转） |
| 车轮节点 | 节点原点 = 车轮中心；车轮的滚动轴 = 节点的**局部 X 轴**；节点的缩放为 (1,1,1) |
| 材质命名 | 车漆 `paint`（会被程序换色）、玻璃 `glass`、刹车灯 `light_brake`、前大灯 `light_head`、尾灯 `light_tail`。其他材质名随意 |
| 面数 | 整车 ≤ 150k 三角面（车身 ≤ 120k，每个车轮 ≤ 7.5k） |
| 贴图 | 每张 ≤ 2048×2048，最多 8 张 |
| 文件大小 | 优化后 ≤ 12 MB |

各车尺寸：

| 车 | 轴距 | 轮距 | 车轮半径 | 参考车身长×宽×高 |
|---|---|---|---|---|
| hatch 雨燕 GTi | 2.60 m | 1.54 m | 0.315 m | 4.25 × 1.80 × 1.44 m |
| coupe 朱雀 R | 2.65 m | 1.58 m | 0.335 m | 4.45 × 1.87 × 1.30 m |
| rally 雷隼 AWD | 2.62 m | 1.56 m | 0.325 m | 4.40 × 1.80 × 1.47 m |

**版权提醒**：请使用自己有权使用的模型（自建、CC0、或已购买许可）。不要使用真实品牌的车标和商标。

## 9.4 HDRI、贴图与景物

| 文件 | 要求 |
|---|---|
| `valley_sky.hdr` | 等距柱状投影（2:1），Radiance HDR 格式，2048×1024（可选 4096×2048），晴朗的上午、太阳高度约 40°，地平线以下最好是草地或山地 |
| `coast_sunset.hdr` | 同上，黄昏，太阳高度约 10°，色调偏暖 |
| `waternormals.jpg` | 无缝平铺的水面法线贴图，512×512 或 1024×1024 |
| 路面等贴图 | 无缝平铺，正方形，1024 或 2048。albedo 为 sRGB；normal 为 OpenGL 方向（+Y 向上，也就是"绿色朝上"）；rough 为灰度图。沥青贴图对应 8×8 m 的实际面积，草地、砾石为 4×4 m，岩石为 9×9 m，混凝土为 2×2 m |
| `scenery/tree_a.png`、`tree_b.png`、`tree_c.png` | 对应云杉、银冷杉、高山五针松的整树备用贴图，用生图模型绘制。保留透明边缘和树种各自的宽高比，树干底部对齐，用于远景。 |
| `scenery/tree_sprays.png` | 近景树木共用的 512×512 RGBA 图集。三个格子分别放置绘制的云杉、银冷杉和高山五针松枝叶，第四格为树皮。 |
| 树 `tree_*.glb` | 高 6–14 m，原点在树干底部中心，+Y 向上，≤ 8k 三角面，叶子用 alpha-test 材质（`alphaMode: MASK`） |
| 石头 `rock_*.glb` | 直径 1–3 m，原点在底部中心，≤ 2k 三角面 |
| `start_gantry.glb` | 横跨路面的龙门架，内侧净宽 ≥ 16 m，原点在路面中心，+Z 为赛车前进方向 |
| `grandstand.glb` | 看台，约 30×8×12 m，原点在底部中心，+Z 朝向赛道 |
| `lighthouse.glb` | 灯塔，高约 24 m，原点在底部中心 |

## 9.5 音频

| 文件 | 要求 |
|---|---|
| `engine_on_*.wav` | 单声道 WAV，44.1 kHz / 16 bit，**能无缝循环**，时长 1–3 s；在稳定转速下带负载（踩油门）录制，转速分别约为 2000 / 4000 / 6500 rpm（coupe 的高转速为 6800） |

| `tyre_skid.wav`、`surface_gravel.wav`、`wind.wav` | 单声道，可无缝循环，2–4 s |
| `impact_light.wav`、`impact_heavy.wav`、`shift.wav` | 单声道，单次播放，≤ 1 s |

## 9.6 加载器 —— `src/assets/assetManager.ts`（Codex 实现）

```ts
export class AssetManager {
  constructor(baseUrl: string);                                  // 通常为 'assets/'
  loadManifest(): Promise<Manifest>;                             // 缺失时返回空 manifest（所有字段为空）
  loadGLB(path?: string): Promise<THREE.Group | null>;           // 失败返回 null
  loadTexture(path?: string, srgb?: boolean): Promise<THREE.Texture | null>;
  loadHDR(path?: string): Promise<THREE.DataTexture | null>;
  loadAudio(ctx: AudioContext, path?: string): Promise<AudioBuffer | null>;
  onProgress: (loaded: number, total: number) => void;
}
```

- GLTFLoader 要设置 `setMeshoptDecoder(MeshoptDecoder)`（从 `three/examples/jsm/libs/meshopt_decoder.module.js` 导入）。
- 每个文件只加载一次（以路径为键缓存 Promise）。
- 404、网络错误或解析错误：返回 null，`console.info('[assets] missing', path)`，**不抛异常**。
- 进度：只统计本次请求的文件数。

## 9.7 素材校验脚本 —— `scripts/check-assets.mjs`（Codex 实现）

`npm run assets:check` 读取 `public/assets/manifest.json`，对每一项：

1. 文件不存在 → 打印 `MISSING  <path>（将使用占位）`，不算错误。
2. `.glb`：用 `@gltf-transform/core` 的 `NodeIO` 读取，检查：
   - 车辆：是否存在 `body`、`wheel_FL/FR/RL/RR` 节点；车轮节点的世界坐标与 9.3 尺寸表的误差 ≤ 0.02 m；是否存在 `paint` 材质；三角面总数 ≤ 150000。
   - 景物：三角面数在 9.4 的上限以内。
3. 贴图：读取 JPEG/PNG 文件头里的宽高，检查是否为正方形，以及边长是否 ≤ 2048（HDR 不检查）。
4. WAV：读取文件头，检查声道数为 1、采样率为 44100。

输出每一项 `OK` / `WARN <原因>` / `MISSING`，最后打印汇总。只有 manifest 本身无法解析时，退出码才为 1。

## 9.8 素材优化脚本 —— `scripts/optimize-assets.mjs`（Codex 实现）

`npm run assets:optimize -- <输入.glb> <输出.glb>`，调用：

```
npx gltf-transform optimize <in> <out> --compress meshopt --texture-compress webp --texture-size 2048
```

（用 `child_process.spawnSync`，`stdio: 'inherit'`，`shell: process.platform === 'win32'`。）用户把原始模型放进来之前先跑这个脚本。
